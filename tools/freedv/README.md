# FreeDV reference tooling

`sources.json` records the first-milestone source pins and speech fixture hashes.
`reference_benchmark.py` runs the upstream FreeDV transmit and receive tools on
an exact pinned fixture. Both executables must already be built. Example, with
paths adjusted for the local source/build locations:

```sh
python3 tools/freedv/reference_benchmark.py --mode 700E \
  --tx /path/to/codec2-build/src/freedv_tx --rx /path/to/codec2-build/src/freedv_rx \
  --input /path/to/codec2/raw/ve9qrp_10s.raw --output /path/to/new-results

python3 tools/freedv/reference_benchmark.py --mode RADE-V1 \
  --tx /path/to/rade-build/src/rade_tx_wav --rx /path/to/rade-build/src/rade_rx_wav \
  --input /path/to/rade_c/input_sample.wav --output /path/to/new-results
```

The output directory must not exist. Each run writes logs and `result.json`;
its temporary audio files are deleted. Fixture hashes are checked before running.
The real-time factor is whole-file wall time divided by input duration, including
process and file I/O. It is an **unpaced reference measurement**, not the planned
30-minute streaming benchmark, p99 block-time test or an on-radio qualification.
It does not access or control the radio. The complete milestone scope and its
outstanding requirements are in `docs/freedv/milestone-1.md`.

`validate_rade_v1_loss.sh` runs the upstream `rade_c_v1_wav` feature-loss
check with the pinned RADE and RADAE sources and the expected input hash. It
requires a built RADE tree and a Python environment with PyTorch, NumPy and
Matplotlib. Pass RADAE source, RADE source, RADE build, Python interpreter and a
new output directory, in that order. It preserves each tool's exit status and
requires the upstream `PASS` marker. This is a host reference check, not RF or
radio performance validation.

`codec2_frame_bench.c` is a separate 700E codec-only prototype. Build it against
the pinned Codec2 headers and library, for example:

```sh
cc -std=c11 -Wall -Wextra -Werror -I/path/to/codec2/src \
  tools/freedv/codec2_frame_bench.c -L/path/to/codec2-build/src -lcodec2 -lsamplerate -lm -o /tmp/codec2-frame-bench
/tmp/codec2-frame-bench tx /path/to/codec2/raw/ve9qrp_10s.raw 10 paced resample 1
```

For RX, pass a raw 8 kHz signed-16 modem fixture generated by the pinned
`freedv_tx 700E` tool and use `rx` instead of `tx`. Fixtures repeat from memory;
the program has no radio or physical audio I/O. It reports frame timing ratios,
deadline misses and Linux peak RSS as JSON. The optional `resample 1` arguments
exercise stateful 44.1-to-8 kHz and 8-to-44.1 kHz libsamplerate conversion,
including the output conversion to signed 16-bit PCM, and
exclude one second of audio from timing. The 8 kHz fixture is converted to
44.1 kHz before measurement, then repeated from memory. Omit both arguments for
the original codec-only timing. Unpaced runs report deadline misses as null.
Full-pipeline qualification remains false: RADE, live audio-device scheduling,
queue/underrun accounting and on-radio validation are not implemented.
Do not use its numbers to claim the milestone performance gate passed.
The prototype has been exercised both natively and under ARM/QEMU. QEMU timing
is not representative of the radio, and the Debian ARM build is not a deployable
substitute for the matching X6200 Buildroot SDK.

`rade_frame_bench.c` is a separate in-memory RADE V1 streaming prototype. It
includes LPCNet speech feature extraction for TX, the RADE modem, FARGAN speech
synthesis for RX, and stateful 44.1 kHz input/output resampling. It accepts a
raw signed-16 mono PCM fixture: 16 kHz speech for TX, or an 8 kHz real modem
signal for RX. `continuous` repeats the fixture; RX `interrupt` injects two
seconds of silence every 12 seconds. It uses no physical audio or radio devices.

Build and run its host smoke checks against the pinned RADE C build and its
patched, static Opus tree (with libsamplerate development headers installed):

```sh
opus_dir=/path/to/rade-build/build_opus-prefix/src/build_opus
cc -O2 -std=c11 -Wall -Wextra -Werror -Wno-error=cpp \
  -I/path/to/rade_c/src -I"$opus_dir/dnn" -I"$opus_dir/celt" \
  -I"$opus_dir/include" -I"$opus_dir" tools/freedv/rade_frame_bench.c \
  -L/path/to/rade-build/src -lrade "$opus_dir/.libs/libopus.a" \
  -lsamplerate -lm -Wl,-rpath,/path/to/rade-build/src -o /tmp/rade-frame-bench
python3 tools/freedv/test_rade_frame_bench.py --benchmark /tmp/rade-frame-bench \
  --tx /path/to/rade-build/src/rade_tx_wav --speech /path/to/rade_c/input_sample.wav
```

The test verifies the pinned speech WAV hash, generates a modem fixture using
the reference transmitter, and checks TX, synchronized RX, no-sync silence,
interruptions and pacing. The benchmark reports block ratios and durations,
deadline misses, sync and output counters, model/speech initialization time,
and Linux peak RSS; warm-up is excluded from timing. Unpaced deadline misses
are null. It does not yet measure queues, underruns, progressive RSS, CPU or
temperature, make a result bundle, or use the radio's matching SDK. Neither
its host results nor its estimated timing gate qualify the target radio. Its
third-party notice is in `THIRD-PARTY-NOTICES.md`.

`diagnostic_state.c` is an isolated session-state prototype. It does not control
the radio, provide synchronization, capture snapshots, or implement the diagnostic
UI. Its caller must serialize access, stop audio and clear software TX when
requested, and complete restoration before calling `fd_restored`. It rejects
remote arming, invalid TX permission and unknown, stale or transmitting packet
status. After stopping, the caller must confirm that audio was flushed and
software commands cleared, then provide a later fresh packet reporting RX before
restoration. Packet sequence numbers, a reliable watchdog, actual exclusive
ownership and snapshot/restore are not yet wired into the radio. Compile and run
the behavioral check with:

```sh
cc -std=c11 -Wall -Wextra -Werror tools/freedv/diagnostic_state.c \
  tools/freedv/diagnostic_state_test.c -o /tmp/freedv-state-test
/tmp/freedv-state-test
```

With diagnostics enabled, `src/freedv/capture_ring.c` provides a bounded,
single-producer/single-consumer buffer at the existing PulseAudio callback
before application decimation. The capture is the existing **mono** 44.1 kHz
stream, not independent ALSA channel readback. Overflow and PulseAudio holes
are counted; the callback never writes files. Start/stop APIs are internal and
are not wired to the UI or an exclusive session yet. They must not be used as
a radio qualification tool until the session owner, worker, export and safety
behavior are implemented. The host test covers ordering, overflow, holes and
cursor wrap, including concurrent transfer. A separate mocked PulseAudio test
exercises the real callback, its holes/errors, capture stop and reset, and the
unchanged delivery to the application's DSP.

`src/freedv/watchdog.c` is an opt-in, monotonic-clock timeout primitive for a
future diagnostic session. It starts disarmed, refuses a second arm or a timeout
over 10 seconds, invokes the callback once on expiry or timer failure, and waits
for a running callback before cancellation completes. Its callback and radio
shutdown path are not connected yet; it cannot by itself stop audio, clear TX,
or guarantee the required 500 ms RF cessation. Never hold the radio lock while
cancelling or closing it, and do not call those operations from the callback.
The host test exercises expiry, cancellation and callback synchronization.

`src/freedv/wav_capture.c` adds a background writer for that queue. It creates
new mode-0600 mono PCM WAV files at the capture sample rate, drains the queue
outside the callback and reports audio holes, overflow and I/O failures to a
caller-provided abort callback. The owner must serialize start/stop, establish
an exclusive diagnostic session first, and never stop or join from that
callback or while holding the radio lock. Failed starts can leave a partial file;
existing files are never overwritten. This worker is not wired to the UI or to
radio TX cleanup and is not ready for hardware qualification. Store captures
outside Git and share them only deliberately.

The opt-in control-owner lease can refuse a diagnostic claim when a remote
owner is active or the radio state is not RX, and it prevents remote control
claims from taking the lease. It is not yet wired to the diagnostic page and
does **not** block all local TX/audio writers, active workers or hardware PTT.
Those exclusions and fresh packet checks are prerequisites for a real session.

The model names all eight RECORD × MODEM × software-PTT combinations and treats
each as potentially keyed. Selection itself only changes model state; every
matrix case requires local arming. Its separate passive-RX selection does not
authorize routing changes or generated playback.

For the host GUI build, configure with `-DENABLE_FREEDV_DIAGNOSTICS=ON` and run
`ctest --test-dir build-host -R '^freedv_diagnostic_state$' --output-on-failure`.
The option defaults to OFF. When enabled on X6200 or the host simulator,
Settings → Info includes a read-only snapshot of cached route commands, the
last radio state and the most recent baseband packet's TX flag and age. It does
not acquire a session, run experiments, or key RF; the values are refreshed when
the Info page opens. Cached commands are not hardware readback, and unknown or
old packet status must not be taken as proof that RF has stopped.

With a freshly started host simulator and `tesseract` installed, run
`python3 tools/freedv/host_ui_check.py` to exercise opening Settings. Add
`--snapshot` for a diagnostics-enabled build to check the displayed route
snapshot. The helper drives host FIFOs and reads only the local simulator screen;
do not use it on a physical radio.

To also test decoding the X6200 control library's cached RECORD, MODEM and PTT
bits, provide `-DX6200_CONTROL_INCLUDE_DIR=/path/to/X6200Control/include` when
configuring the host build and build target `freedv_x6200_route_test`. Run
`ctest --test-dir build-host -R '^freedv_' --output-on-failure`. This mocked
test covers all eight bit combinations; it does not read actual hardware.
`radio_get_commanded_audio_route()` reads those commands under the radio lock;
it returns the last known state and timestamped packet TX flag separately and
is not a complete route snapshot. Before the first packet, or if the supplied
clock predates the packet, the packet status is unknown. A caller must decide
which packet age is usable; this accessor does not decide whether RF is safe.
The packet sequence advances with each observation and saturates rather than
wrapping; it can distinguish a later packet from one received before a stop.

The opt-in internal `radio_get_freedv_cached_snapshot()` reads selected X6200
register-cache fields under the radio lock: shared route bits, mic selection and
gains, line levels, speaker and monitor settings, requested power, VFOs, modes,
and RX filter. These are cached commands, not independent baseband measurements.
The raw shared word also contains unrelated bits and must never be restored
wholesale. ALSA channel settings, application audio levels and overrides, exclusive
ownership and restoration are not implemented. The host backend exposes simulated
values and marks the X6200 raw word unavailable; it is not hardware evidence.

`inventory.py --output /path/to/new-inventory.json` collects kernel, CPU,
memory and available thermal information, firmware metadata files, ALSA and
PulseAudio endpoints, and read-only ALSA mixer contents. It does not query the
baseband; record that version separately from the radio's Info page. Missing
commands and observations are recorded as unavailable. It does not collect
station configuration databases or change radio settings. Device names and
mixer details may be identifying; inspect the output before sharing. The
inventory is not a hardware routing or TX test.

`collect_benchmark.py` runs a prebuilt in-memory 700E or RADE V1 benchmark and
creates a **new local directory** containing a versioned source and hash
manifest, benchmark output and log, timestamped start/exit events, and sampled
Linux process memory, CPU frequency policies and available thermal/cooling
observations. Optional `--model` arguments record hashes of model artifacts;
compare these hashes with the pinned sources before accepting a result. Missing
system observations are null or empty, not evidence of an absence of throttling.
For example:

```sh
python3 tools/freedv/collect_benchmark.py --mode 700E --benchmark /path/to/codec2-frame-bench \
  --fixture /path/to/codec2/raw/ve9qrp_10s.raw --direction tx --seconds 30 \
  --pacing paced --warmup 5 --sample-interval 10 --output /path/to/new-result
```

For RADE, set `--mode RADE-V1` and supply its benchmark and appropriately rated
raw fixture. `--workload interrupt` is available for RADE RX. Resource sampling
adds system load; record its interval and use it consistently. The collector
does not command the radio, include recordings, or upload data. It cannot supply
the missing queue/underrun measurements, controlled RF input, or route and
restoration observations. Its output alone is not the complete milestone result
bundle and cannot qualify a radio performance gate.

For a shared X6100 compile check, build the pinned X6100Control and libgpiod
v1 sources from `sources.json` into a host-only prefix, with the ordinary host
GUI dependencies already prepared by `host/build.sh build`. Then use:

```sh
prefix=/path/to/host-only-x6100-deps
export CPATH="$prefix/include${CPATH:+:$CPATH}"
export LIBRARY_PATH="$prefix/lib${LIBRARY_PATH:+:$LIBRARY_PATH}"
export LD_LIBRARY_PATH="$prefix/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
cmake -S . -B /path/to/new-x6100-host-build -G Ninja -DHOST_BUILD=ON \
  -DHW_BACKEND=x6100 -DENABLE_FREEDV_DIAGNOSTICS=ON -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build /path/to/new-x6100-host-build --target x6100_gui
```

The combined diagnostic prototypes were compiled and linked this way using
the recorded control-library and libgpiod commits. Do not execute the resulting
physical-backend binary as a simulator. This host build does not use the radio's
Buildroot SDK and is not suitable for deployment. CI separately compiles the
X6100 backend against the pinned control headers; it is not a full target build.
